01What Tomcat does

A servlet is a Java class that runs inside Tomcat and handles requests from a browser. It reads the incoming request, executes Java code, and prepares a response.

In a console application, you start your program with:

CMD
java App

Java calls the entry point:

Java
public static void main(String[] args)

With a servlet application, you start Tomcat. It waits for HTTP requests and calls the appropriate methods in your servlet. You do not write a main() method for each servlet.

ResponsibilityWho handles it?
Listen for browser connectionsTomcat
Read and interpret HTTP requestsTomcat
Find the servlet mapped to the requested URLTomcat
Execute your application logicYour servlet
Choose the response contentYour servlet
Send the HTTP response to the browserTomcat

Tomcat is called a servlet container because it loads, initializes, and manages servlets. Tomcat 10.1 implements Jakarta Servlet 6.0, so our imports use jakarta.servlet. Older tutorials often use javax.servlet; those imports do not match this setup. Tomcat documentation ↗

Compilation and execution: For the servlet classes in this tutorial, you compile .java files with javac. Tomcat loads the resulting .class files and runs them inside the JVM.

02From a URL to Java code

Suppose you open:

Browser URL
http://localhost:8080/ServletDemo/hello
  1. The browser sends an HTTP GET request to Tomcat.
  2. Tomcat identifies the application: /ServletDemo.
  3. Tomcat finds the servlet mapped to /hello.
  4. Tomcat supplies request and response objects.
  5. The servlet’s doGet() method executes.
  6. Tomcat sends the resulting response to the browser.

The browser receives response content. Your Java code executes on the server.

URL partMeaning
httpCommunication protocol
localhostThe computer running the browser itself
8080Tomcat’s default HTTP port
/ServletDemoApplication context path
/helloPath mapped to a servlet inside that application
A servlet URL does not have to match a filename. /hello is a mapping we define.

03Your first servlet

Create the project directory below. We will keep Java source code in src and the deployable application in web.

Project directory
C:\Sapir_JavaCourse_14\ServletDemo

Create src\demo\HelloServlet.java inside the project and insert this complete code:

src/demo/HelloServlet.java
package demo;

import java.io.IOException;
import java.io.PrintWriter;
import java.time.LocalDateTime;

import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet("/hello")
public class HelloServlet extends HttpServlet {

    @Override
    public void init() {
        System.out.println("HelloServlet initialized");
    }

    @Override
    protected void doGet(
            HttpServletRequest request,
            HttpServletResponse response) throws IOException {

        String name = request.getParameter("name");

        if (name == null || name.isBlank()) {
            name = "Guest";
        }

        response.setContentType("text/plain;charset=UTF-8");

        PrintWriter out = response.getWriter();

        out.println("Hello, " + name + "!");
        out.println("This response was generated by a Java servlet.");
        out.println("Server time: " + LocalDateTime.now());
    }

    @Override
    public void destroy() {
        System.out.println("HelloServlet destroyed");
    }
}

This servlet greets the visitor, displays the server’s current time, and logs its initialization and destruction. The next sections explain how each part works; compilation and deployment commands follow in section 9.

04Understanding the servlet class

The package and superclass

package demo; places the class in the demo package. Its full Java name is demo.HelloServlet. We explain packages in more detail in section 11.

Java
public class HelloServlet extends HttpServlet

extends HttpServlet gives our class the standard behavior needed to handle HTTP requests. We customize that behavior by overriding methods such as doGet() and doPost().

The inherited service() method selects the appropriate handler based on the HTTP method. You normally leave service() alone. HttpServlet API ↗

The URL mapping

Java
@WebServlet("/hello")

This annotation registers the servlet and maps it to /hello within the application. The complete request path is /ServletDemo/hello.

Tomcat processes the annotation during deployment. This simple application does not need a web.xml file to register its servlets. WebServlet API ↗

The method declaration

Java
@Override
protected void doGet(
        HttpServletRequest request,
        HttpServletResponse response) throws IOException
PartMeaning
@OverrideAsks the compiler to verify that this method overrides an inherited method
protectedThe inherited method’s access level; appropriate when overriding it
voidThe method does not return a Java value
doGetHandles HTTP GET requests
requestProvides information sent by the client
responseLets us construct the reply
throws IOExceptionAllows input/output failures to propagate to the container
Although the method returns void, it still sends content by writing to response.

05Request parameters and response content

Think of request as the incoming information and response as the outgoing answer.

Reading a parameter

Java
String name = request.getParameter("name");

If the browser requests the URL below, name contains Yossef:

Browser URL
http://localhost:8080/ServletDemo/hello?name=Yossef

The part after ? is the query string. Separate multiple parameters with &:

Query string
?name=Yossef&course=Java
Java
String name = request.getParameter("name");
String course = request.getParameter("course");

getParameter() returns a String, or null if the parameter was not supplied. Numeric input needs conversion and validation. For ordinary HTML forms, the same method also reads submitted form fields. ServletRequest API ↗

Java
if (name == null || name.isBlank()) {
    name = "Guest";
}

This fallback handles both a missing parameter and an empty name. Java evaluates || from left to right and short-circuits: when name == null is true, it does not call isBlank().

Writing a response

Java
response.setContentType("text/plain;charset=UTF-8");
PrintWriter out = response.getWriter();
out.println("Hello, " + name + "!");

The content type tells the browser that the body is plain text encoded as UTF-8. getWriter() gives us a writer for that body. Set the content type and encoding before obtaining the writer. ServletResponse API ↗

Java
System.out.println("Message for the server console");
response.getWriter().println("Message for the browser");

These two statements have different destinations: server output versus the HTTP response.

Generating HTML

A servlet can also generate HTML. As an alternative, replace the response-writing block with:

Java
response.setContentType("text/html;charset=UTF-8");

response.getWriter().println("""
        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <title>Servlet Response</title>
        </head>
        <body>
            <h1>Hello from Java!</h1>
            <p>This HTML was generated by a servlet.</p>
        </body>
        </html>
        """);

The browser renders these tags. The triple quotes form a Java text block, supported by the Java 21 setup used here. If you insert user input into HTML later, escape it for its HTML context. Our greeting example returns plain text.

06GET versus POST

GETPOST
Usual purposeRetrieve informationSubmit information for processing
Servlet handlerdoGet()doPost()
Ordinary HTML form dataAdded to the URL query stringSent in the request body
ExampleView a courseSubmit course registration
Should it intentionally change application data?NoIt can

Typing a URL into the browser address bar causes a GET request. A form with method="post" causes a POST request when submitted. Both handlers can be implemented in the same servlet if needed.

POST does not itself encrypt data. HTTPS provides encryption in transit.

07Build the registration form

Create web/register.html inside your project. This form submits a student’s name and selected course:

web/register.html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Course Registration</title>
</head>
<body>

    <h1>Course Registration</h1>

    <form action="register" method="post" accept-charset="UTF-8">

        <p>
            <label for="studentName">Student name:</label>
            <input
                type="text"
                id="studentName"
                name="studentName"
                required>
        </p>

        <p>
            <label for="course">Course:</label>
            <select id="course" name="course">
                <option value="java">Java Fundamentals</option>
                <option value="web">Web Development</option>
            </select>
        </p>

        <button type="submit">Submit</button>

    </form>

</body>
</html>
HTMLMeaning
action="register"Submit to register, relative to the current page URL
method="post"Send a POST request
name="studentName"Send the input under the parameter name studentName
value="java"Send java when that option is selected
requiredAsk the browser to reject an empty input

When the page is served at /ServletDemo/register.html, the relative action resolves to /ServletDemo/register.

The servlet reads the name attribute, not the id. The id connects the label to its input and can also be used by CSS or JavaScript.

08Process the form with doPost()

Create src\demo\RegistrationServlet.java and insert:

src/demo/RegistrationServlet.java
package demo;

import java.io.IOException;
import java.io.PrintWriter;

import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet("/register")
public class RegistrationServlet extends HttpServlet {

    @Override
    protected void doPost(
            HttpServletRequest request,
            HttpServletResponse response) throws IOException {

        request.setCharacterEncoding("UTF-8");
        response.setContentType("text/plain;charset=UTF-8");

        String studentName = request.getParameter("studentName");
        String courseCode = request.getParameter("course");

        if (studentName == null || studentName.isBlank()) {
            response.setStatus(HttpServletResponse.SC_BAD_REQUEST);
            response.getWriter().println("Student name is required.");
            return;
        }

        String courseName;

        if ("java".equals(courseCode)) {
            courseName = "Java Fundamentals";
        } else if ("web".equals(courseCode)) {
            courseName = "Web Development";
        } else {
            response.setStatus(HttpServletResponse.SC_BAD_REQUEST);
            response.getWriter().println("Please select a valid course.");
            return;
        }

        PrintWriter out = response.getWriter();

        out.println("Registration details received.");
        out.println("Student: " + studentName.trim());
        out.println("Course: " + courseName);
        out.println();
        out.println("This demonstration does not save the registration.");
    }
}

The method sets the request encoding before reading form parameters. It then validates the submitted values. Browser validation helps users, but requests can come from other programs, so the server must validate them too.

"java".equals(courseCode) works even if courseCode is null: it returns false.

For invalid input, SC_BAD_REQUEST sets HTTP status 400. The following return stops execution before the success response. For valid input, the normal response status is 200 OK.

This servlet only overrides doPost(). Opening /register directly sends GET and normally produces 405 Method Not Allowed. Open register.html and submit the form to test POST.

09Compile and deploy on Windows

These commands use your Tomcat installation and are intended for Windows Command Prompt (CMD). Java 21’s javac should be available in your PATH.

1. Define the Tomcat directory

CMD
set "TOMCAT_DIR=C:\Sapir_JavaCourse_14\Dependecies\apache-tomcat-10.1.59"

The variable is available in this CMD window. The spelling Dependecies matches your existing directory.

2. Open the project and prepare the output folder

CMD
cd /d C:\Sapir_JavaCourse_14\ServletDemo
mkdir web\WEB-INF\classes

If the output directory already exists, you can skip mkdir.

3. Compile both servlet classes

CMD
javac -encoding UTF-8 -cp "%TOMCAT_DIR%\lib\servlet-api.jar" -d web\WEB-INF\classes src\demo\*.java
Command partPurpose
javacRun the Java compiler
-encoding UTF-8Read source files as UTF-8
-cp "…servlet-api.jar"Make the servlet API available during compilation
-d web\WEB-INF\classesPlace compiled classes in the application’s class directory
src\demo\*.javaCompile the Java files in this source folder

HttpServlet is not part of the standard JDK. The compiler finds it in Tomcat’s servlet-api.jar. Tomcat supplies this API at runtime, so do not copy that JAR into the application.

Your deployable files should now be:

Path relative to webPurpose
register.htmlPublic HTML form
WEB-INF\classes\demo\HelloServlet.classCompiled greeting servlet
WEB-INF\classes\demo\RegistrationServlet.classCompiled registration servlet

The compiler creates the demo directory because the classes declare package demo;. Tomcat loads application classes from WEB-INF/classes; files under WEB-INF are not directly accessible through browser requests.

4. Stop Tomcat if it is running

CMD
call "%TOMCAT_DIR%\bin\shutdown.bat"

Wait until Tomcat has stopped before copying the application.

5. Copy the application into webapps

CMD
xcopy web "%TOMCAT_DIR%\webapps\ServletDemo" /E /I /Y

This copies the contents of web into the deployed application. /E includes subdirectories, /I treats the destination as a directory, and /Y overwrites existing files without prompting.

6. Start Tomcat

CMD
call "%TOMCAT_DIR%\bin\startup.bat"

The application directory name gives it the context path /ServletDemo. You do not need a Tomcat Manager account for this folder-based deployment. Tomcat deployment guide ↗

7. Try the application

  • Greeting with the default name
  • Greeting for Yossef
  • Registration form

These links work on the computer where your Tomcat application is running. Open the registration form through Tomcat, rather than double-clicking its HTML file.

10Lifecycle and shared servlet instances

StageMethodWhen it happens
Initializationinit()Once per servlet instance, before handling requests
Request handlingservice(), which dispatches to doGet(), doPost(), etc.For each request
Removaldestroy()During normal servlet removal or application shutdown

Without a startup-loading setting, initialization can wait until the servlet is first needed. Our console messages let you observe initialization and destruction. destroy() is not guaranteed after an abrupt process termination. Jakarta servlet lifecycle ↗

Tomcat normally reuses a servlet instance for many requests, and requests may execute concurrently. HttpServlet API ↗

Avoid storing the current request’s student name in a servlet field:

Java
// Unsuitable for storing the current request's student:
private String studentName;

If two requests modify this field, one student’s value can overwrite another’s. Our code uses a local variable inside the handler instead:

Java
String studentName = request.getParameter("studentName");

Each method invocation has its own local variable. This does not automatically make shared mutable objects safe; those require additional care.

11Folder versus Java package

A folder is a location in the filesystem. A package is a namespace in Java that groups classes and gives them a qualified name. They correspond in our project, but they are different concepts.

Folder demoPackage demo
Created byMaking a directoryWriting package demo; in Java code
PurposeOrganize files on diskOrganize and identify Java classes
Examplesrc\demo\HelloServlet.javademo.HelloServlet
Creating the folder alone does not put a class into a package. The package declaration does that.
Minimal package example — not the servlet implementation
package demo;

public class HelloServlet {
}
  • Class name: HelloServlet
  • Package name: demo
  • Fully qualified class name: demo.HelloServlet

If you remove package demo;, the class belongs to the unnamed package, even when its source file is inside a folder named demo.

Java projects conventionally align source folders with package names:

Package declarationSource file location
package demo;src\demo\HelloServlet.java
package college.servlets;src\college\servlets\HelloServlet.java

For the minimal package-only example above, compiling with:

CMD — minimal package example
javac -d out src\demo\HelloServlet.java

creates:

Compiled file
out\demo\HelloServlet.class

The compiler uses the package declaration to create that structure. out is the output root; demo represents the package. The real servlet also needs the API classpath shown in section 9.

Our deployed servlet follows the same rule:

Deployed class
WEB-INF\classes\demo\HelloServlet.class
NameRole
ServletDemoApplication directory and context path
demoJava package
HelloServletJava class
/helloServlet URL mapping
The Java package demo does not determine the browser URL. The URL uses the application context /ServletDemo and the mapping @WebServlet("/hello").
